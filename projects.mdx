# Projects

DataRelay Labs products share a practical relay philosophy, but each product is independent and solves a different class of problem.

<CardGroup cols={2}>
  <Card title="DataRelay Link" icon="link" href="https://link.datarelay.run/">
    **Secure connectivity for private, isolated, and restricted networks.**

    Use Link when the problem is controlled connectivity: Remote Access to selected internal services, Internet Access from restricted hosts, or permission-bounded AI Access to private targets.
  </Card>

  <Card title="DataRelay Control" icon="sliders" href="https://control.datarelay.run/">
    **Enterprise data-flow processing, governance, and delivery.**

    Use Control when the problem is application data movement: collect once, process per Route, protect where needed, and deliver to one or many Destinations.
  </Card>
</CardGroup>

## Product comparison

| | DataRelay Link | DataRelay Control |
| --- | --- | --- |
| Primary problem | Controlled network / AI connectivity | Enterprise data integration and delivery |
| What moves | Connections and authorized operations | Application data / events |
| Typical flow | Outside → Remote Service; Managed Host → approved Internet; AI Identity → approved target permissions | Source → Stream → Routes → Destinations |
| Main control | Which source, destination, service, identity, and permission may connect | Which records/fields go where and how they are processed |
| Typical scale | Approximately 1–50 Managed Hosts | Enterprise data-flow pipelines |
| Product dependency | None | None |
