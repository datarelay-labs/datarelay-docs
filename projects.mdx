# Projects

DataRelay Labs products share a practical relay and control philosophy, but each product is independent and solves a different class of problem.

<CardGroup cols={3}>
  <Card title="DataRelay Link" icon="link" href="https://link.datarelay.run/">
    **Secure connectivity for private, isolated, and restricted networks.**

    Use Link when the problem is controlled connectivity: Remote Access to selected internal services, Internet Access from restricted hosts, or permission-bounded AI Access to private targets.
  </Card>

  <Card title="DataRelay Control" icon="sliders" href="https://control.datarelay.run/">
    **Enterprise data-flow processing, governance, and delivery.**

    Use Control when the problem is application data movement: collect once, process per Route, protect where needed, and deliver to one or many Destinations.
  </Card>

  <Card title="DataRelay Grant" icon="shield-check" href="https://grant.datarelay.run/">
    **Human approval before automated execution.**

    Use Grant when an operation should not proceed until an explicit human decision has been recorded. The product is currently Coming Soon and is based on US 12,056,667 B1 and KR 10-2567118 B1.
  </Card>
</CardGroup>

## Product comparison

| | DataRelay Link | DataRelay Control | DataRelay Grant |
| --- | --- | --- | --- |
| Primary problem | Controlled network / AI connectivity | Enterprise data integration and delivery | Human approval and execution gating |
| What moves | Connections and authorized operations | Application data / events | Approval requests, decisions, and controlled execution signals |
| Typical flow | Outside → Remote Service; Managed Host → approved Internet; AI Identity → approved target permissions | Source → Stream → Routes → Destinations | Request → Human Approval → Controlled Execution |
| Main control | Which source, destination, service, identity, and permission may connect | Which records/fields go where and how they are processed | Whether a requested action may proceed after an explicit human decision |
| Typical integration | Network and AI access paths | Enterprise data-flow pipelines | Link, Control, or external systems that need approval gates |
| Product dependency | None | None | None; planned as an optional shared approval layer |
