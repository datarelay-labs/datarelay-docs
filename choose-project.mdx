# Choose by Problem

Select the problem closest to your environment. Each card opens the relevant product site or current product documentation.

<CardGroup cols={2}>
  <Card title="I need remote access behind NAT/firewalls" icon="arrow-right-to-bracket" href="https://link.datarelay.run/">
    **DataRelay Link — Remote Access** exposes only approved internal Remote Services instead of joining entire networks.
  </Card>

  <Card title="I need controlled Internet access from a restricted network" icon="arrow-up-right-from-square" href="https://link.datarelay.run/">
    **DataRelay Link — Internet Access** lets managed or protected sources reach only policy-approved external destinations through explicit Network and Service Objects.
  </Card>

  <Card title="I need controlled AI access to private targets" icon="robot" href="https://link.datarelay.run/">
    **DataRelay Link — AI Access** uses verified AI Identity plus explicit target and Permission Objects. The MCP Bridge is part of the current v2.4 development target and remains subject to release qualification.
  </Card>

  <Card title="I need to collect, process, and deliver enterprise data" icon="arrows-left-right" href="https://control.datarelay.run/">
    **DataRelay Control** collects data once, applies route-specific Transform, Protection, and Policy, then delivers it to one or many Destinations.
  </Card>

  <Card title="I need a human approval before an automated action runs" icon="shield-check" href="https://github.com/datarelay-labs/datarelay-grant-docs">
    **DataRelay Grant** is the coming-soon approval and execution-control layer for Request → Human Approval → Controlled Execution workflows.
  </Card>

  <Card title="I am not sure which product fits" icon="circle-question" href="/projects">
    Compare DataRelay Link, DataRelay Control, and DataRelay Grant by problem, operating model, and product boundary.
  </Card>
</CardGroup>

<Note>
  DataRelay Link, DataRelay Control, and DataRelay Grant are independent products. Grant is planned as an optional approval layer that can complement Link, Control, or external systems; it is not a required runtime component of either product.
</Note>
