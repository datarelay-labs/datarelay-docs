# 설계 철학

DataRelay Labs 제품들은 서로 독립적이지만, 몇 가지 실용적인 엔지니어링 원칙을 공유합니다.

  </Card>

  <Card title="필요한 것만 Relay" icon="filter">

  </Card>
</CardGroup>

## 조직 구조

`datarelay.run`은 **DataRelay Labs 조직 포털**입니다. 제품 문서는 `link.datarelay.run`, `control.datarelay.run`, `grant.datarelay.run`처럼 각 제품 전용 사이트에서 관리합니다.

이 구조를 유지하면 제품 수가 늘어나도 최상위 도메인의 역할은 바뀌지 않고, 새 제품을 기존 제품의 Module처럼 보이게 만들지 않으면서 자연스럽게 추가할 수 있습니다.

Grant는 **제품의 독립성과 의도적인 상호 연동을 동시에 유지할 수 있다는 예시**이기도 합니다. Link와 Control은 Grant 없이 독립적으로 사용할 수 있지만, 실행 전에 사람의 승인이 필요한 경우 Grant를 선택적인 Approval Gate로 호출할 수 있습니다.

## 공통 Engineering Lifecycle

Runtime 독립성이 각 Repository가 서로 다른 개발 방식을 사용한다는 의미는 아닙니다. DataRelay Labs는 Repository 초기화, Design Gate, AI 기반 구현 Handoff, Validation 선택, PR/CI Review, Release Evidence, 운영, Session Continuity에 공통 Engineering System을 사용합니다.
