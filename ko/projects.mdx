# 프로젝트 소개

DataRelay Labs의 제품들은 공통적인 Relay 및 Control 철학을 공유하지만, 서로 독립적이며 해결하는 문제도 다릅니다.

<CardGroup cols={3}>
  <Card title="DataRelay Link" icon="link" href="https://link.datarelay.run/">
    **사설망·폐쇄망·제한망을 위한 Secure Connectivity 제품입니다.**

    연결 제어가 문제일 때 사용합니다. 외부에서 승인된 Remote Service로 접근하고, 제한망 Managed Host가 승인된 Internet Destination에 접속하며, 검증된 AI Identity가 허용된 Target/Permission 범위에서만 동작하도록 합니다.
  </Card>

  <Card title="DataRelay Control" icon="sliders" href="https://control.datarelay.run/">
    **Enterprise Data Flow의 처리, Governance, 전달을 위한 제품입니다.**

    Application Data Movement가 문제일 때 사용합니다. 데이터를 한 번 수집하고 Route별로 처리·보호한 뒤 하나 이상의 Destination으로 전달합니다.
  </Card>

  <Card title="DataRelay Grant" icon="shield-check" href="https://github.com/datarelay-labs/datarelay-grant-docs">
    **자동 실행 전에 사람의 승인을 두기 위한 제품입니다.**

    중요한 작업이 명시적인 사람의 결정 없이 실행되어서는 안 되는 경우 사용합니다. 현재 Coming Soon 단계이며 US 12,056,667 B1 및 KR 10-2567118 B1 특허를 기반으로 제품을 정의하고 있습니다.
  </Card>
</CardGroup>

## 제품 비교

| | DataRelay Link | DataRelay Control | DataRelay Grant |
| --- | --- | --- | --- |
| 주요 문제 | Network / AI Connectivity 제어 | Enterprise Data Integration / Delivery | Human Approval / Execution Gating |
| 이동 대상 | Connection 및 승인된 AI Operation | Application Data / Event | 승인 요청, 승인 결정, 통제된 실행 신호 |
| 대표 흐름 | 외부 → Remote Service, Managed Host → 승인된 Internet Destination, AI Identity → 승인된 Target/Permission | Source → Stream → Routes → Destinations | 요청 → 사람의 승인 → 통제된 실행 |
| 핵심 제어 | 어떤 Source/Destination/Service/Identity/Permission이 연결 가능한가 | 어떤 Record/Field를 어디로 어떤 형태로 전달하는가 | 요청된 작업이 사람의 명시적 승인 후 실행 가능한가 |
| 대표 연동 | Network 및 AI Access 경로 | Enterprise Data Flow Pipeline | 승인 Gate가 필요한 Link, Control 또는 외부 시스템 |
| 제품 의존성 | 없음 | 없음 | 없음. 선택적인 공통 승인 계층으로 연동 예정 |
